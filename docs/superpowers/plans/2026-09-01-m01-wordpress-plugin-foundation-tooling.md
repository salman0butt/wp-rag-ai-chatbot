# M01 WordPress Plugin Foundation & Tooling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish a minimal activatable WordPress plugin with PHP/TypeScript quality tooling, reproducible WordPress smoke testing, CI, and a clean distribution package foundation.

**Architecture:** Keep the WordPress entry file declarative and thin. It loads Composer, delegates hook registration to `WpRagAiChatbot\Core\Bootstrap`, and keeps lifecycle callbacks in `WpRagAiChatbot\Core\Lifecycle`; there is no product/RAG/database behavior in M01. JavaScript tooling uses official `@wordpress/scripts` and `@wordpress/env`, but Node remains development/build tooling only.

**Tech Stack:** PHP 8.2+, WordPress 6.9+, Composer 2, PHPUnit 10.5, Brain Monkey 2.7, PHPStan 2.2 + `szepeviktor/phpstan-wordpress`, WordPress Coding Standards 3.4.1+, Node.js LTS (22+ accepted), TypeScript, `@wordpress/scripts` 34.2+, `@wordpress/env` 11.14+, Jest through `wp-scripts`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-01-wp-rag-ai-chatbot-master-design.md`

## Global Constraints

- WordPress/PHP is the mandatory server runtime.
- Minimum WordPress baseline is 6.9 for this implementation program unless a later compatibility finding is recorded in `docs/DECISIONS.md`.
- Minimum PHP version is 8.2.
- Do not introduce a mandatory Node.js/Python/LangChain/LangGraph service.
- Do not introduce Redis, RabbitMQ, Kafka, Temporal, or another mandatory external queue.
- External vector databases remain optional adapters.
- No product database schema, providers, RAG, admin UI, or frontend widget behavior is implemented in M01.
- No production behavior is written before its failing behavior test unless the TDD skill explicitly permits an exception.
- WordPress Coding Standards are mandatory; PSR-4 class filenames are allowed by a narrowly documented PHPCS exclusion rather than abandoning WPCS.
- Secrets, `.env` files, tests, docs, development manifests, and `node_modules` must not enter the plugin ZIP.

## File Structure Locked by This Plan

- `wp-rag-ai-chatbot.php` — sole WordPress plugin entry file and plugin headers; delegates immediately to Composer + `Bootstrap`.
- `src/Core/Bootstrap.php` — registers lifecycle and `plugins_loaded` hooks; no domain behavior.
- `src/Core/Lifecycle.php` — activation/deactivation boundary reserved for later migration/job work; M01 callbacks are intentionally side-effect free.
- `composer.json` — PHP runtime floor, PSR-4 autoload, QA/test commands and dev dependencies.
- `phpunit.xml.dist` / `tests/bootstrap.php` — isolated unit test runtime.
- `tests/Unit/PluginEntryPointTest.php` — validates plugin metadata, ABSPATH guard, Composer loading and bootstrap delegation.
- `tests/Unit/Core/BootstrapTest.php` — verifies WordPress hooks are registered with exact callbacks.
- `phpcs.xml.dist` — WordPress rules and project exclusions.
- `phpstan.neon.dist` — WordPress-aware static analysis.
- `package.json` / `tsconfig.json` — JS/TS build, lint, typecheck, Jest, wp-env and package scripts.
- `src-js/index.ts` / `src-js/index.test.ts` — minimal TDD fixture proving the TypeScript pipeline; it is not enqueued in WordPress yet.
- `.wp-env.json` — WordPress 6.9 / PHP 8.2 baseline integration environment.
- `scripts/test-wp-activation.sh` — repeatable activation/deactivation smoke check against wp-env.
- `readme.txt` / `LICENSE` — initial WordPress distribution metadata/license.
- `.github/workflows/ci.yml` — PHP, JS, WordPress smoke, and package jobs.
- `docs/milestones/M01-wordpress-plugin-foundation-tooling.md` and progress ledgers — verification evidence and state recovery.

namespace WpRagAiChatbot\Core;

final class Lifecycle
{

    {
    }

    public static function deactivate(): void
    {
    }

Create `src/Core/Bootstrap.php`:

```php
<?php

declare(strict_types=1);

namespace WpRagAiChatbot\Core;

final class Bootstrap
{
    public static function register(string $pluginFile): void
    {
        register_activation_hook($pluginFile, [Lifecycle::class, 'activate']);
        register_deactivation_hook($pluginFile, [Lifecycle::class, 'deactivate']);
        add_action('plugins_loaded', [self::class, 'load']);
    }

    public static function load(): void
    {
        do_action('wp_rag_ai_chatbot_loaded');
    }
}
```

Create `wp-rag-ai-chatbot.php` with the WordPress plugin header, GPL metadata, `Requires at least: 6.9`, `Requires PHP: 8.2`, text domain `wp-rag-ai-chatbot`, ABSPATH guard, `vendor/autoload.php` loading, and exactly:

```php
use WpRagAiChatbot\Core\Bootstrap;

Bootstrap::register( __FILE__ );
```
